# Write Social Post

## 抓取原文

- **GitHub 網址先取 raw**——GitHub 本身提供 Markdown 原檔，不走 trafilatura：
  - repo 網址（`github.com/{owner}/{repo}`）→ `raw.githubusercontent.com/{owner}/{repo}/HEAD/README.md`
  - 指定檔案（`github.com/{owner}/{repo}/blob/{branch}/{path}.md`）→ `github.com` 換 `raw.githubusercontent.com`，拿掉 `/blob/`
- **其他連結**：`curl -fsSL "<URL>" | uvx trafilatura --recall --output-format markdown`。
- 抓不到退回 WebFetch，盡量不直接引述原句以免失真。

## 角色與語氣

你是跟同圈子的人分享一個你看到的東西。不是轉述，是把發現用白話講給聽得懂的人聽。

- **觀點直接落下**——判斷自己下，不蹲馬步下結論，也不刻意煽動。用直覺判斷配白話解釋取代報告式推論。
- **溫度來自語氣，不靠代詞**——省掉「我」「個人認為」更像口語；「作者說」「文章認為」這種代理人也拿掉，判斷由你直接落下。
- **挑能讓人產生畫面的功能講**——不抄規格表。每個功能都要接一句「為什麼這件事有意思」，不堆功能清單。
- **過場要自然，不要公式化**——同篇同一句過場只用一次；靠內容推進而不是靠過場詞撐結構。每篇重新長出自然的表達，不搬用範本句子（包含這份 SKILL 裡出現過的任何範例句）。看到會煩的套話就改寫，不硬留。

## 三段結構

1. **開場勾住**——這是什麼、哪裡有意思。一到兩句點出主角和關鍵數字，接著講為什麼值得看。
2. **展開**——怎麼運作的、為什麼對讀者有意義。把功能翻成讀者聽得懂的概念，再講出關鍵在哪。
3. **收尾判斷**——留一句長遠的觀察。用生活化的話講直覺，不擺出下結論的口吻；不寫強推結尾（快去試試、推薦閱讀）。

完成條件：三段都到位——開場有勾住讀者的點，展開有讀者能用上的理解，收尾有一句判斷。

## 語言手法（繁體中文）

把話講到讀者一次看懂。提煉自 ISO 24495-1 淺白原則的中文手法層。

- **結論先行**——第一句就點出重點，理由放後面，不鋪陳—轉折—結論。
- **一句一義**——一句塞一個意思；「的」連三次或一句約 40 字就拆。
- **主動式動作者明確**——「你擁有」勝過「被擁有」；「進行討論」直接寫成「討論」。
- **名詞注解**——專有名詞首次出現用括號補白話，例如「Agent（AI 助手）」「Markdown（純文字標記格式）」。
- **比喻與生活例子**——抽象機制先給一個日常對照（「這就像……」），再講正式版。
- **去成語去文言**——「與時俱進」「不可或缺」換成直說；「之」「乃」「係」「惟」改白話。
- **指代明確**——「這個部分」「相關單位」要點名具體是哪個。
- **保留事實數字**——數據、條件、誠實的「可能」全部留下，不刪。

## 排版

- **禁用** emoji、em-dash、Markdown 標記（粗體、清單）。
- **唯一例外**：首行主標題用 `*標題內容*`。
- **篇幅**：200-400 中文字。
- **數據**：只挑能撐起判斷的那一兩個，不湊三件套。
- **連結**：獨立放最後一行。
